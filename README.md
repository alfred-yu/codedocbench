# CodeDocBench

面向 C 项目的代码文档生成桌面工具：解析 C/C++ 源码中的符号（函数、结构体、枚举、宏、全局变量等），引导用户构建文档目录树，关联低层需求（LLR）Excel，最终生成结构化的代码文档 Excel。适用于 DO-178C 等对需求追溯有严谨要求的场景。

## 功能特性

### 四步向导流程

应用按「层层递进」的向导组织，每一步需完成前置步骤后才能进入：

1. **选择与解析项目** —— 点击左侧「打开项目目录」卡片选择 C 项目根目录，自动扫描解析；支持通过右键菜单「刷新项目」（全量重扫）与「关闭项目」。项目与目录树持久化到本地，重启应用自动恢复。
2. **构建文档目录树** —— 左侧自由添加/重命名/删除章节（支持展开、折叠、批量展开折叠）；右侧项目文件树支持**按文件后缀筛选**、**目录/文件节点勾选**（父子联动、半选状态），勾选后一键挂载到选中的章节下。挂载的 `.c` 文件自动生成 5 个数据子章节（Type / Global Variable / Macro / Constant / Function Definition），`.h` 文件生成 4 个（不含 Function Definition）。
3. **关联低层需求** —— 选择低层需求 Excel 并映射列：章节列、ID 列、需求内容列、Object Type 列，带数据预览。
4. **生成文档** —— 以表格预览将要导出的 Excel 全部内容（与导出文件同源同构），确认后一键导出本地 Excel。

顶部导航条提供「上一步 / 下一步」与步骤跳转；已到达的步骤可回退，未解锁步骤不可跳越。

### 解析能力（Python 后端，解析器 v1.2.0）

基于轻量分词器 + 文件作用域规则的确定性解析，同一输入永远得到同一输出：

- 函数定义/声明（含返回类型、参数、行号）、结构体/联合/枚举及成员、typedef、全局变量、宏与常量（数值/字符串字面量归类为常量）、`#include`
- 正确处理：字符串/字符字面量与注释的词法安全、多行宏续行、`#if 0` 分支剔除（`#else` 分支保留）、`int a, b` 多声明符展开、函数指针全局变量、花括号初始化、头文件保护宏（include guard）过滤
- 已知边界：不做完整预处理（宏展开）与完整 C 文法解析，无法识别的片段容错跳过
- 每次解析输出 `parserVersion / lineCount / mtime` 元数据，供追溯与缓存失效判断

### Excel 导出格式

| 列 | 说明 |
|---|---|
| 章节号 | 按目录树层级生成，如 `1.1.2` |
| 需求内容 | 标题行（有章节号）**加粗**；数据行为符号名；解析不到时为 `N/A` |
| Object Type | 数据行来自源码解析为 `Source Code`；占位行（`N/A`）为 `Comment` |
| Parent ID | 仅函数符号行填写：该函数在低层需求文档中所有需求内容行的 ID（换行分隔，排除 `Comment` 行）；其余行为空 |

**Parent ID 关联规则**：低层需求文档中「文档编号到函数名为止」——需求内容列的值恰为函数名的行是函数名行，其后直到下一个标题行（章节列非空或下一个函数名行）之前的行都是该函数的需求内容行，排除 Object Type 为 `Comment` 的行后取其 ID 集合。参考 `PDT_LLR_Requirements.xlsx` 的组织方式。

导出前自动执行一致性自检（行号越界、重复符号、章节列未映射等），异常时由用户确认后才继续。

## 技术架构

```
┌─────────────────────────────────┐
│  前端  原生 JS + Vite（WebView） │  界面 / 向导状态机 / 目录树 / 预览
├─────────────────────────────────┤
│  桥接  Tauri 2 (Rust)           │  scan_dir / parse_file / save_file /
│                                 │  read_file / file_mtime
├─────────────────────────────────┤
│  解析  Python 子进程            │  backend.py：分词器 + 文件作用域规则
└─────────────────────────────────┘
```

- **前端**：原生 JavaScript（无框架）+ Vite 构建，`xlsx-js-style` 读写 Excel（支持单元格样式）
- **桥接层**：Rust 将命令转发给 Python 子进程（UTF-8 JSON stdout），任一环节失败均返回可读的错误 JSON
- **解析器**：纯 Python 标准库实现（无第三方依赖）

## 目录结构

```
├── index.html               # 应用入口（四个步骤面板 + 导航条）
├── src/
│   ├── main.js              # 前端逻辑：向导状态机、目录树、挂载、导出
│   └── style.css            # 设计体系（设计令牌 / 组件 / 布局）
├── src-tauri/               # Tauri 壳（Rust 命令桥接）
├── python/backend.py        # C 源码解析器（scan_dir / parse_file）
├── tests/
│   └── test_backend_parse.py  # 解析准确性回归测试（金标准基线）
├── samples/cproject/        # 示例 C 项目
└── dist/                    # 前端构建产物
```

## 环境要求

- Node.js ≥ 18
- Rust（含 Cargo）
- Python ≥ 3.10（仅标准库）
- Windows 下需 WebView2 Runtime

## 开发与构建

```bash
npm install            # 安装前端依赖

npm run tauri dev      # 桌面开发模式（自动启动 Vite 与 Tauri 窗口）
npm run dev            # 仅前端（浏览器预览，Tauri 命令不可用）
npm run build          # 前端构建（输出到 dist/）
npm run tauri build    # 打包桌面应用
```

## 测试

```bash
python -m pytest tests/ -v
```

`tests/test_backend_parse.py` 是解析器的金标准回归基线（16 例），覆盖基础符号识别、多行宏、条件编译剔除、多声明符、函数指针、头文件保护宏过滤、词法安全、元数据字段，以及对 `samples/` 真实文件的冒烟检查。**修改 `backend.py` 解析规则后务必运行**，防止精度回退。

## 数据持久化

| 数据 | 位置 |
|---|---|
| 上次项目根 / 目录树快照 | localStorage `lastProjectRoot` / `lastProjectTree` |
| 文档目录树（按项目隔离） | localStorage `docTree:<项目根路径>` |
| 解析结果缓存 | 内存（按文件 mtime 失效，文件被外部修改后自动重析） |
