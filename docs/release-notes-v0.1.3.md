# CodeDocBench v0.1.3

> C/C++ 项目代码文档生成与 DO-178C 双向追溯工具 · Windows 桌面应用（免 Python）

## 本版重点

修复一个**会导致追溯错误**的缺陷：不同源码文件里有同名函数时（典型是各模块都用 `static` 定义同名私有函数），Parent ID 会串号——把一个函数的需求填到另一个文件里去。

这不是"填不出来"，而是"**填错了**"，在 DO-178C 场景下比空值危险得多。

## 变更明细

### 修复：同名函数跨文件串号（0c76896）

**问题**：Parent ID 关联索引以「纯函数名」为键，同名函数只保留一份需求块，于是所有同名函数行被填上同一份 Parent ID。而步骤 5 的链接生成走独立路径，此前**连告警都没有**，直接静默产出错误关联。

**消歧规则**：低层需求中每个函数需求块都带章节号，取「同目录级别」（章节号去掉最后一段）的其他函数块作为其兄弟函数；若某个兄弟函数名出现在当前源码文件里，则该块属于该文件。

> 例：`mod_a.c` 与 `mod_b.c` 各有一个 `static void A(void)`。低层需求里 A 有两个块：一处与 `a_helper1` / `a_helper2` 同目录（这两个函数只在 `mod_a.c` 里），另一处与 `b_helper1` / `b_helper2` 同目录。据此可正确区分归属。

**判定不出来时绝不随便填**：该块同目录下没有其他函数可作参照、或多个块都像是，一律留空，并在三个地方提示——

- 步骤 5 预览区列出「同名函数无法判定归属」的具体函数与文件
- 步骤 5 统计栏显示警示
- 导出链接文件前弹确认

### 修复：一致性报告把未决单列（1f2bb9f）

上一条的空值语义是「**填不出来**」，而非「该函数没有需求」。若把它混进统计，用户会把工具局限误判成数据缺陷。故在报告里单列为「未决」：

- **不计入**「Parent ID 为空」，也**不计入**「未被引用」
- 汇总页新增独立的「同名函数未决」小节（函数名 / 代码侧行数 / 需求侧条数 / 处理建议）
- 两张明细表里未决行标为「（同名函数无法判定归属）」/「（归属未决）」，用**浅琥珀色**底纹，与真问题的**浅红色**一眼可分
- 两张环形图把未决单列为第三段
- 导出摘要弹窗单独说明

口径不变式：**已关联 + 未决 + 遗漏 = Source Code 总数**、**已引用 + 未决 + 孤儿 = Requirement 总数**。

### 修复：步骤 5 链接失效保护（1c0e5aa）

生成链接文件后，若上游数据变动（目录树增删改、换需求文件、改列映射、需求文件被外部程序改、刷新项目），已生成的结果会**作废并在预览区提示原因**，防止导出过期数据。导出入口另有兜底重算比对，拦住不经过界面交互的改动路径。

### 解析器 v1.3.0（5325b1b）

- 函数章**只输出定义**：同文件的原型声明与 `extern` 引用不再重复出文档
- `#define` 归入宏、文件级 `const` 归入常量，全局变量只留真正可变的
- 生成侧与校验侧口径统一（`globals` 与 `functions` 两章记 `Source Code`，其余记 `Comment`）

### 文档（3fda6a7）

用户手册第 6 节补全为完整用法（含实机截图）、新增同名消歧与报告口径说明；README 同步 Object Type 口径与仓库迁移信息。

## 升级注意

**若你的项目存在跨文件同名函数，建议导出后核对一致性检查报告的「同名函数未决」小节**：

- 该小节为空 → 所有函数都已唯一关联
- 非空 → 这些函数的 Parent ID 留空。请核对低层需求中它们是否分属不同章节；补齐能区分它们的同目录兄弟函数后重新导出即可自动关联

低层需求文件中**同名函数分属不同章节**是可正常处理的情况，无需修改源码。

## 安装

下载对应安装包（MSI 或 NSIS）后运行即可，**无需另装 Python**（解析器已随应用打包）。

- Windows MSI：`CodeDocBench_0.1.3_*_x64_en-US.msi`
- 安装版：`CodeDocBench_0.1.3_*_x64-setup.exe`

## 校验

安装包文件名带版本号，可用 SHA-256 校验完整性（值见 Release 页面）。
